SecureBank AI API workflows

How each of the 16 REST endpoints under /api/v1 handles a request, step by step, as implemented in the FastAPI source. The language model is Google Gemini (gemini-3.5-flash, embeddings gemini-embedding-001); MySQL is the system of record.

Every request

All endpoints share this path. Validation errors stop at FastAPI before any business code runs; business-rule failures are raised as BankingError and turned into a JSON error with the right status by one handler in app/main.py.

Request / response Validation and security MySQL Gemini, LangGraph, RAG, MCP Business rule in code Error exit Early return, not an error Success

Platform

01 GET /api/v1/health Public

Health check

Liveness and database check that load balancers and monitors call first. It never fails with an error: a database problem is reported in the body.

Request
No body, no token.
Success
200 {"status": "ok" | "degraded", "app", "database": "up" | "down: …", "llm_model": "gemini-3.5-flash"}

Auth

02 POST /api/v1/auth/login Public

Log in

Exchanges email and password for a signed JWT. The same error is returned for an unknown email and a wrong password, so the API never reveals which emails exist.

Request
{"email": "aarav@securebank.test", "password": "Password@123"}
Success
200 {"access_token", "token_type": "bearer", "expires_in": 3600, "customer_id", "role"}
03 GET /api/v1/customers/me Bearer JWT

My profile

Returns the logged-in customer's profile. The customer is resolved from the token's sub claim; no ID is taken from the URL or body.

Request
Header Authorization: Bearer <token>
Success
200 {"customer_id", "full_name", "email", "phone", "kyc_status", "credit_score", "monthly_income"}

Accounts

04 GET /api/v1/accounts Bearer JWT

List my accounts

Lists only the caller's accounts. The query is filtered by the customer_id from the token, so another customer's accounts can never appear.

Request
Header Authorization: Bearer <token>
Success
200 [{"account_no", "account_type", "balance", "currency", "status", "daily_transfer_limit"}]
05 GET /api/v1/accounts/{account_no}/balance Bearer JWT

Account balance

Returns the balance of one account if the caller owns it. Someone else's account returns 404, not 403, so its existence is not revealed.

Request
Path account_no, e.g. SB1001
Success
200 {"account_no", "balance", "currency", "status", "as_of"}
06 GET /api/v1/accounts/{account_no}/transactions Bearer JWT

Account transactions

Returns the latest ledger rows for one owned account, newest first, with optional CREDIT/DEBIT filter.

Request
Path account_no · Query limit=10 (1–100), txn_type=CREDIT|DEBIT (optional)
Success
200 [{"txn_id", "txn_type", "amount", "description", "counterparty_account", "reference_no", "status", "created_at"}]

Transfers

07 POST /api/v1/transfers Bearer JWT

Fund transfer

Moves money atomically. A repeated Idempotency-Key returns the first result instead of debiting twice; both rows are locked in sorted order so opposite transfers cannot deadlock; every rule is re-checked under the lock.

Request
Header Idempotency-Key (8–64 chars) · {"from_account": "SB1001", "to_account": "SB1002", "amount": 2000, "remarks": "Dinner"}
Success
201 {"reference_no": "TXN…", "status": "SUCCESS", "from_account", "to_account", "amount", "new_balance", "message"}

Loans

08 POST /api/v1/loans/eligibility Bearer JWT

Loan eligibility + EMI

Rule-based decision, no LLM. A rejection is a normal 200 answer with decision REJECTED and the reasons, not an error.

Request
{"loan_type": "PERSONAL" | "HOME" | "CAR", "amount": 500000, "tenure_months": 36}
Success
200 {"decision": "APPROVED" | "REVIEW" | "REJECTED", "interest_rate", "emi", "foir_percent", "reasons": [...]}
09 GET /api/v1/loans Bearer JWT

My loans

Lists the caller's existing loans, the same rows whose EMIs feed the FOIR check.

Request
Header Authorization: Bearer <token>
Success
200 [{"loan_id", "loan_type", "principal", "interest_rate", "tenure_months", "emi", "status"}]

Tickets

10 POST /api/v1/tickets Bearer JWT

Raise dispute ticket

Creates a support ticket with a priority taken from dispute_policy.md. A linked transaction must belong to the caller; one of INR 50,000 or more is always HIGH priority.

Request
{"category": "UNAUTHORIZED_TXN" | "FAILED_TXN" | "CARD" | "GENERAL", "description": "≥ 10 chars", "txn_id": 12}
Success
201 {"ticket_id", "category", "description", "txn_id", "priority", "status": "OPEN", "created_at"}
11 GET /api/v1/tickets/{ticket_id} Bearer JWT

Ticket status

Returns one ticket if it belongs to the caller; any other ticket ID returns 404.

Request
Path ticket_id (integer)
Success
200 {"ticket_id", "category", "priority", "status", "created_at", …}

RAG

12 POST /api/v1/rag/ingest Admin JWT

Ingest policies

Admin only. Rebuilds the Chroma collection from the policy Markdown files, so running it twice never duplicates chunks. Run it once before policy questions, and again after changing the embedding model.

Request
No body. Token must have role ADMIN (admin@securebank.test).
Success
200 {"documents": 5, "chunks": 13, "collection": "bank_policies"}
13 POST /api/v1/rag/query Bearer JWT

Policy Q&A

Answers only from retrieved policy text. If the answer is not in the context, the prompt forces a fixed refusal pointing to the branch helpline.

Request
{"question": "What is the IMPS limit?", "k": 4}
Success
200 {"answer", "sources": ["fund_transfer_policy.md"], "chunks_used": 4}

Agent

14 POST /api/v1/agent/chat Bearer JWT

LangGraph assistant

One chat turn through the LangGraph agent. The thread is namespaced as customer_id:thread_id so nobody can resume another customer's conversation. A transfer stops at the approval step and returns awaiting_approval.

Request
{"message": "Transfer 2000 from SB1001 to SB1002 for dinner", "thread_id": "t1"}
Success
200 {"thread_id", "status": "completed" | "awaiting_approval", "intent", "answer", "sources", "pending_transfer"}
15 POST /api/v1/agent/approve Bearer JWT

Approve transfer

Resumes a paused graph with the customer's decision. Approval runs the same atomic transfer as POST /transfers, with idempotency key agent-<request_id>; rejection moves no money.

Request
{"thread_id": "t1", "approved": true}
Success
200 {"status": "completed", "intent": "transfer", "answer": "Done. … Reference TXN…"}

MCP

16 GET /api/v1/mcp/tools Bearer JWT

List MCP tools

Shows the 7 tools the MCP server publishes, with their full input schemas. Tool definitions are loaded once and cached; with stdio transport the first call starts the MCP server as a child process.

Request
Header Authorization: Bearer <token>
Success
200 [{"name": "get_account_balance", "description", "input_schema"}, … 7 tools]
